Hexkit is a browser toolkit for working with EVM transactions. It decodes calldata,
looks up function signatures, builds and simulates transactions, explores verified
source, inspects contract storage, steps through execution, and deposits into yield
vaults across chains.

Everything runs client-side against public RPCs and provider APIs. There is no
account to create and no server holding your keys.

Try it at [web3-toolkit.vercel.app](https://web3-toolkit.vercel.app), or run it
locally with the [Quickstart](/quickstart).

## The modules

| Module | What it does |
|---|---|
| Decoder | Decodes raw calldata against known or supplied ABIs |
| Signature database | Resolves 4-byte selectors and event topics |
| Transaction builder | Composes calls and encodes arguments |
| Simulation | Runs a transaction and reports asset changes before you sign |
| Source explorer | Fetches verified source and diffs contract upgrades |
| Storage viewer | Reads and annotates contract storage slots |
| Debugger | Steps through execution, backed by the Rust EDB service |
| LI.FI Earn | Deposits into and withdraws from yield vaults, across chains |
| AI concierge | Suggests vaults and assembles multi-leg rebalance plans |

Every module except the debugger runs without any backend beyond the provider
proxies described in [Configuration](/configuration).

## How cross-chain works

The Earn module's cross-chain routes use intent orders rather than bridging
directly: your input is escrowed on the source chain and a solver delivers the
output on the destination chain, then claims the escrow by proving delivery.

That model explains the deadlines, the four-step timeline, and the refund path you
will see in the UI. [How intent orders work](/concepts/intent-orders) covers it.

<Note>
  Hexkit is a tool for inspecting and constructing transactions, not financial
  advice. Simulate before you sign, and confirm the asset changes match what you
  expect.
</Note>
